## Що ви отримуєте

Запитайте LLM — отримайте реальні зміни інфраструктури на вашому сервері FastPanel:

> **Ви:** «Створи новий сайт `foo.example.com` для користувача `www-root`, PHP 8.4, без бази даних, та підключи наш wildcard SSL-сертифікат. Також увімкни HTTP/2 та HTTP/3.»
>
> **LLM (~30 секунд, 5 викликів інструментів пізніше):** Сайт з id 53 доступний за адресою https://foo.example.com з HTTP/2, HTTP/3, wildcard TLS та автоматично налаштованим переадресуванням на HTTPS.

> **Ви:** «Покажи мені конфігурацію nginx для сайту 1 — перевір, чи блокує він `.env`, `.git` та інші чутливі шляхи. Якщо ні — додай захист.»
>
> **LLM:** Читає конфігурацію, зауважує, що `.env` та `.htaccess` роздаються як статичні файли (діра в безпеці), редагує фронтенд для додавання правил заборони для прихованих файлів + чутливих розширень + файлів фреймворку, попередньо переглядає різницю через `dry_run`, після чого розгортає зміни. `.env` тепер повертає 404; `.well-known/acme-challenge` продовжує працювати.

> **Ви:** «Які сайти запущено на цьому сервері, хто ними володіє та на яких не примусово увімкнено HTTPS?»
>
> **LLM:** Запитує `sites_list` і повідомляє про 5 сайтів без `https_redirect: true`.

## Можливості

- **32 інструменти**, що охоплюють сайти, бази даних (зокрема SSH-дамп/імпорт), користувачів, DNS-зони, SSL-сертифікати, навантаження системи, чергу, журнали сайтів, плани резервного копіювання, діагностику на рівні хоста, завантаження/розгортання файлів у веброот сайту, а також «сирі» конфігурації nginx/apache/php.ini.
- **Модель безпеки з двома токенами.** Операції читання використовують токен лише для читання; операції зміни даних вимагають окремого токена запису (`FASTPANEL_WRITE_TOKEN`). Якщо токен запису не встановлено, кожен інструмент запису відмовляє в доступі.
- **`confirm: true` обов'язковий** для кожного запису. Випадкові виводи LLM не можуть змінювати стан.
- **`dry_run: true` для попереднього перегляду** точного тіла HTTP-запиту, який було б надіслано серверу — паролі замінені на `***`, мережевий виклик не виконується.
- **Компактний режим відповіді** у sites_list для запобігання переповненню контексту LLM на великих панелях.
- **Журнал аудиту в stderr** для кожного виконаного запису з прихованими паролями.
- **Анотації інструментів MCP** (`readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint`), щоб клієнти та сканери правил коректно класифікували кожен інструмент, а не сприймали діагностику лише для читання як деструктивну.
- **Автоматична перевірка `nginx -t` з відкатом** — `site_configuration_update` перевіряє живу конфігурацію після застосування та автоматично відкочує невдале редагування, якщо налаштовано SSH.
- **Протестовано на живій панелі FastPanel 2** із 35+ сайтами в продакшні.

## Навіщо це потрібно

FastPanel не публікує специфікацію OpenAPI. Кінцеві точки та форми корисних навантажень у цьому сервері були отримані шляхом зворотньої розробки Angular SPA-бандлу панелі та перехоплення запитів у DevTools, включаючи неочевидні особливості, як-от:

- Кінцеві точки списків вимагають параметрів, загорнутих у `filter[limit]=…&filter[type]=…` — просте `?limit=…` мовчки ігнорується.
- Створення сайту — це двоетапний майстер (`POST /api/master/domain` — зондування → `PUT /api/master` — фактичне створення), а не звичайний `POST /api/sites`.
- Поле `backend` у конфігурації сайту є конфігурацією пулу PHP-FPM, коли `handler=php_fpm`, але блоком Apache VirtualHost, коли `handler=fcgi`.
- Підключення/від'єднання SSL відбувається через `PUT /api/sites/{id}` (на стороні сайту), а не `POST /api/sites/{id}/certificate` (такої кінцевої точки не існує).

Це задокументовано в описах інструментів, щоб LLM не потребував повторного відкриття цих особливостей.

- Node.js 20 або новіший

## Встановлення

```bash
git clone https://github.com/iMateo/fastpanel-mcp.git
cd fastpanel-mcp
pnpm install      # або: npm install
pnpm build
```

## Отримання API-токенів

На хості FastPanel (під root) створіть токен лише для читання для повсякденного використання:

```bash
mogwai users tokens add -n mcp-read -s read_only -e 2030-12-31
```

> Бінарний файл CLI знаходиться за адресою `/usr/local/fastpanel2/fastpanel`; нові збірки FastPanel роблять його доступним через `PATH` як `mogwai` (`/usr/local/bin/mogwai` → той самий бінарний файл). Стара документація називає його `fastpanel`, якого **немає** в `PATH` — використовуйте `mogwai` або повний шлях. Лише для root.

Скопіюйте поле `msg` із поверненого JSON — це і є ваш токен. Він обходить двофакторну аутентифікацію та зберігається після закінчення сесії, тому поводьтеся з ним як із обліковими даними сервера.

Необов'язковий токен запису з терміном дії та блокуванням IP:

```bash
mogwai users tokens add -n mcp-write -c <your-ip> -e 2030-12-31
```

Залишайте `FASTPANEL_WRITE_TOKEN` невстановленим у конфігураціях, де операції запису не потрібні.

## Налаштування

```bash
cp .env.example .env
```

Мінімально необхідний `.env`:

```
FASTPANEL_URL=https://panel.example.com:8888
FASTPANEL_TOKEN=<your read token>
FASTPANEL_INSECURE_TLS=1   # лише якщо панель використовує самопідписаний сертифікат
```

## Використання з Claude Code

```bash
claude mcp add fastpanel \
  -s user \
  -e "FASTPANEL_URL=https://panel.example.com:8888" \
  -e "FASTPANEL_TOKEN=…" \
  -e "FASTPANEL_INSECURE_TLS=1" \
  -- node $PWD/dist/index.js
```

Додайте `-e "FASTPANEL_WRITE_TOKEN=…"`, якщо хочете увімкнути інструменти запису.

## Інструменти

### Читання (токен запису не потрібен)

| Інструмент | Кінцева точка | Повертає |
|---|---|---|
| `sites_list` | `GET /api/sites/list` | Всі сайти, 13 основних полів за замовчуванням (компактний режим) |
| `site_get` | `GET /api/sites/{id}` | Повний об'єкт сайту з 40 полями (сертифікат, бекенд, резервні копії, статистика) |
| `site_configuration_get` | `GET /api/sites/{id}/configuration` | «Сирий» nginx (фронтенд), бекенд обробника (PHP-FPM або Apache), php.ini |
| `databases_list` | `GET /api/databases` | Бази даних MySQL + PostgreSQL з власниками та розмірами |
| `database_servers_list` | `GET /api/databases/servers` | Доступні сервери баз даних — використовуйте id у `database_create` |
| `users_list` | `GET /api/users` | Користувачі панелі та власники сайтів |
| `dns_domains_list` | `GET /api/dns/domains` | DNS-зони (порожньо, якщо DNS панелі вимкнено) |
| `dns_records_list` | `GET /api/dns/domain/{id}/records` | Записи для однієї зони |
| `certificates_list` | `GET /api/certificates` | Збережені SSL-сертифікати (LE + власні) |
| `system_load` | `GET /api/loads/full` | CPU / пам'ять / диск / середнє навантаження / найактивніші процеси |
| `queue_list` | `GET /api/queue/list` | Фонові завдання, включаючи завершені |
| `queue_active` | `GET /api/queue` | Лише активні завдання (фільтрує завершені) + `meta.all_done` для детермінованого опитування |
| `site_logs` | `GET /api/sites/{id}/log/{lines}/{type}` | Хвіст журналів доступу або помилок nginx/apache (frontend_/backend_) без SSH |
| `site_resources` | `GET /api/sites/{id}/resources` | Бази даних, піддомени, DNS та поштові зони, прикріплені до сайту |
| `backup_plans_list` | `GET /api/v2/backup/plans` | Налаштовані плани резервного копіювання |
| `me` | `GET /api/me` | Обліковий запис поточного токена читання (ім'я користувача, ролі, ssh) |
| `settings_get` | `GET /api/settings` | Загальносистемні налаштування панелі (ОС, ліцензія, ліміти, сповіщення) |

### Запис (вимагає `FASTPANEL_WRITE_TOKEN` + явне `confirm: true`)

| Інструмент | Кінцева точка | Призначення |
|---|---|---|
| `user_create` | `POST /api/users` | Створити нового користувача панелі (власника сайту) |
| `database_create` | `POST /api/databases` | Створити базу даних MySQL або PostgreSQL з виділеним користувачем БД |
| `site_create` | `POST /api/master/domain` + `PUT /api/master` | Атомарно створити сайт, за потреби — з вбудованим користувачем / базою даних / FTP |
| `site_update` | `PUT /api/sites/{id}` | Змінити коренів документів (`index_dir`) / індекс каталогу — наприклад, вказати сайт Laravel на `public/` (пресет `framework: "laravel"`) |
| `site_ssl_update` | `PUT /api/sites/{id}` | Підключити / замінити / від'єднати SSL-сертифікат, перемикати HTTPS / HTTP2 / HTTP3 / HSTS |
| `site_backend_update` | `PUT /api/sites/backend/{backend_id}` | Змінити версію PHP, обробник, порт, сокет, змінні середовища (передавайте id сайту — id бекенду визначається автоматично) |
| `site_configuration_update` | `PUT /api/sites/{id}/configuration` | Замінити «сирий» nginx/apache/php.ini для сайту. **Небезпечно**: невірний синтаксис може зламати сайт — якщо налаштовано SSH, запускає `nginx -t` після застосування та **автоматично відкочує** при помилці (`validate: false` для пропуску) |
| `certificate_create_letsencrypt` | `POST /api/certificates` | Видати новий сертифікат Let's Encrypt (асинхронно — опитуйте `queue_active`) |

### З підтримкою SSH (вимагає `FASTPANEL_SSH_HOST`)

Ці інструменти роблять те, чого не може REST API — вони виконуються безпосередньо на хості панелі. Використання є необов'язковим та не прив'язаним до конкретного хоста: встановіть `FASTPANEL_SSH_HOST` (+ необов'язкові `FASTPANEL_SSH_USER`/`PORT`/`KEY`), щоб вказати на **будь-який** сервер FastPanel. Сервер використовує ваш власний клієнт `ssh`, тому хост повинен бути доступний з автентифікацією за ключем. `nginx_validate` та `site_doctor` доступні лише для читання; решта — операції запису (`confirm: true` + попередній перегляд `dry_run`).

| Інструмент | Виконує | Призначення |
|---|---|---|
| `nginx_validate` | `nginx -t` | Перевірити живу конфігурацію nginx до/після `site_configuration_update` — виявляти синтаксичні помилки до того, як вони покладуть nginx |
| `site_doctor` | `stat` / `systemctl` / `nginx -t` | Діагностувати причину помилок сайту: відсутній docroot, батьківський каталог без `o+x` (пастка 750 → 404), відсутній FPM-сокет, мертвий бекенд, зламана конфігурація nginx |
| `database_dump` | `mysqldump` | Зробити дамп бази даних у файл `.sql` у проміжному каталозі (локальний MySQL). Записує файл, що належить root — вимагає `confirm: true` |
| `database_import` | `mysql` | Завантажити файл `.sql` (із проміжного каталогу) до бази даних. **Деструктивно** — вимагає `confirm: true` |
| `site_files_upload` | `rsync` (запасний варіант scp) | Завантажити локальний файл/каталог у веброот сайту, потім змінити власника на користувача сайту. `delete: true` синхронізує дзеркально (видаляє файли, що є лише на віддаленій стороні) |
| `site_files_deploy` | `git clone` / `curl` + `tar` | Завантажити файли на хост (https git-репозиторій або tarball) у веброот сайту, потім змінити власника на користувача сайту |
| `site_file_put` | `cat` через ssh | Записати один невеликий вбудований файл (заглушка/.htaccess/robots.txt) у веброот сайту, потім змінити власника на користувача сайту |

Шляхи дампу/імпорту обмежені проміжним каталогом (за замовчуванням `/root/fastpanel-mcp-dumps`, можна змінити через `FASTPANEL_DUMP_DIR`); шляхи поза ним або ті, що містять `..`, відхиляються. Три інструменти завантаження/розгортання отримують `index_dir` сайту та його власника через `site_get`, відмовляють у підшляхах призначення, що виходять за межі веброоту або містять небезпечні для оболонки символи, та виконують `chown` усіх файлів на системного користувача сайту, щоб nginx/PHP-FPM міг їх обслуговувати (файли, що належать root, спричинять помилку 403).

## Кулінарна книга

**Розгорнути новий тестовий сайт під wildcard-сертифікатом (30 секунд, без очікування DNS/LE):**

```
site_create(domain="foo.example.com", owner_id=2, php_version="84")
  → site_ssl_update(site_id=<new>, certificate_id=<wildcard>, https_redirect=true, http2=true, http3=true)
```

**Розгорнути продакшн-сайт із новим сертифікатом Let's Encrypt:**

```
site_create(domain="foo.com", aliases=["www.foo.com"], owner_id=<id>, php_version="84", database={...})
  → certificate_create_letsencrypt(site_id=<new>, email, common_name="foo.com")
  → queue_active  # опитувати, поки завдання LE не отримає статус SUCCESS
```

**Посилити стандартний nginx (заблокувати `.git`, `.env`, `.htaccess`, composer.json тощо):**

```
site_configuration_get(site_id)
  # LLM вставляє блоки location безпеки у фронтенд
site_configuration_update(site_id, frontend=<edited>, backend=<unchanged>, phpini=<unchanged>)
```

**Видалити застарілі версії TLS:**

```
site_configuration_get(site_id)
  # LLM замінює "ssl_protocols TLSv1.1 TLSv1.2 TLSv1.3" на "ssl_protocols TLSv1.2 TLSv1.3"
site_configuration_update(site_id, frontend=<edited>, backend=<unchanged>, phpini=<unchanged>)
```

## Модель безпеки

- **Два токени.** Токен читання завжди обов'язковий. Токен запису необов'язковий — якщо `FASTPANEL_WRITE_TOKEN` не встановлено, кожен інструмент запису завершується з помилкою до звернення до мережі з `FastPanelWriteDisabledError`.
- **`confirm: true`** є обов'язковим аргументом для кожного інструменту запису. Інструменти відмовляються виконуватися без нього — це ваш останній рубіж захисту від заплутаного LLM.
- **`dry_run: true`** повертає точне тіло JSON, яке було б надіслано, з паролями, заміненими на `***`, і повністю пропускає HTTP-виклик.
- **Журнал аудиту в stderr** фіксує кожен виконаний запис із прихованим корисним навантаженням. У Claude Code це відображається в журналах MCP.
- **Автоматична перевірка `nginx -t`.** При налаштованому SSH `site_configuration_update` запускає `nginx -t` одразу після застосування та **автоматично відкочує до попередньої конфігурації** у разі невдачі — невдале редагування не може залишити nginx у стані, коли він не може перезавантажитися. Передайте `validate: false`, щоб відмовитися від перевірки.
- **Анотації інструментів.** Кожен інструмент постачається з підказками MCP `readOnlyHint` / `destructiveHint` / `idempotentHint` / `openWorldHint`, щоб клієнти MCP та зовнішні шлюзи правил могли застосовувати відповідні захисні заходи для кожного інструменту.
- **Ще немає інструментів видалення.** Деструктивні операції залишені для інтерфейсу користувача, доки їх не буде навмисно додано.
- **Блокування токенів за IP** (`mogwai users tokens add -c <ip>`), щоб витік токена не міг бути використаний з іншого місця.

## Відомі підводні камені

- **Параметри `filter[...]`:** Кінцеві точки списків FastPanel очікують `filter[limit]=…&filter[type]=…`. Просте `?limit=…` мовчки ігнорується.
- **Створення сайту — це майстер, а не REST-create.** Панель виконує `POST /api/master/domain` (зондування), потім `PUT /api/master` (фактичне створення), а не `POST /api/sites`. `site_create` приховує це.
- **Асинхронні операції.** Видача сертифікатів, оновлення бекенду сайту та деякі інші операції негайно повертають `action: "CREATING"` / `"UPDATING"` і виконуються у фоновому режимі. Використовуйте `queue_active` для опитування.
- **Немає офіційної специфікації OpenAPI.** Кінцеві точки отримані шляхом зворотньої розробки. Якщо новий реліз FastPanel щось зламає, будь ласка, створіть issue з новою формою корисного навантаження.
- **Самопідписаний TLS.** Більшість встановлень панелі використовують самопідписані сертифікати. Встановіть `FASTPANEL_INSECURE_TLS=1` або розмістіть перед панеллю правильний сертифікат.
- **fail2ban / обмеження швидкості.** FastPanel постачається з fail2ban та обмеженням швидкості на рівні панелі. Тестові скрипти, що інтенсивно звертаються до API, можуть призвести до блокування вашої IP-адреси.
